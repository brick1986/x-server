# 开发工具使用指南

本指南供 Codex 和 Claude Code 共同使用。公共协作要求见 [AGENTS.md](../AGENTS.md)，环境与测试命令见 [DEVELOPMENT.md](../DEVELOPMENT.md)。工具名称和参数以当前会话暴露的接口为准，不假定两种工具具有相同的 MCP、权限或 shell 配置。

## 代码理解与检索

- CodeGraph 的使用条件和优先顺序遵循 [AGENTS.md 的 CodeGraph 规则](../AGENTS.md#codegraph)。优先通过 `codegraph_explore` 或 `codegraph explore` 理解符号、调用链和跨模块关系。
- `.codegraph/` 存在不代表索引一定可用；目录可能只有占位文件。索引缺失、过期或工具不可用时，说明限制并转用 IDEA 符号检索或原生搜索、读取工具，不反复重试，也不自行建立索引。
- CodeGraph 已返回且确认覆盖所需范围的当前源码，无需重复读取；输出不完整、索引过期或文件修改后，可直接读取相关文件核实。
- 重载辨析、精确符号位置、调用关系等语义问题，按需使用 IDEA 的符号检索、符号信息及调用分析。
- 第三方依赖的 jar 内源码优先使用 IDEA `read_file`。`<jar路径>!/<包路径>/<类>.java` 是 IDE 虚拟路径，不直接交给普通文件读取工具；不可用时寻找对应源码包。
- 非代码文档、CodeGraph 未覆盖的内容，以及完成必要代码定位后的纯文本匹配，可使用原生文件搜索和读取工具；有 `rg` 时优先使用它。

## 编辑与格式化

- 普通编辑使用当前工具提供的文件编辑能力。
- 跨模块类或方法重命名优先使用 IDEA 语义重构，避免纯文本替换遗漏引用或误改重载。
- 新增或修改 Java 类后，包括测试类，按 [AGENTS.md](../AGENTS.md) 的要求使用 IDEA 格式化，然后验证。
- IDEA 能力依赖 IDE 正在运行且项目已打开。调用失败时按问题选择其他工具继续可完成的工作；不能用回退工具声称完成了 IDEA 专属步骤。

## 构建与验证

- IDEA 文件诊断可用于快速发现类型、导入等问题，但不能替代真实 Maven 构建和测试。
- 验证范围、外部服务要求和测试库配置见 [DEVELOPMENT.md](../DEVELOPMENT.md)。Windows PowerShell 使用 `.\mvnw.cmd`，Git Bash 使用 `./mvnw`；也可使用已配置的 `mvn`。
- 执行后检查本次报告中的失败、错误和跳过情况，并把命令、范围和结果记录到 [PROGRESS.md](../PROGRESS.md)。

## 调试与数据库

- 静态阅读和测试不足以确认行为时再使用调试能力；优先调试具体测试，避免无必要地启动完整应用。
- 启动完整应用做调试前须获得用户确认；当前任务已明确授权该启动操作时不重复询问。完整应用可能连接 Redis/MongoDB 并占用端口。
- 调试结束后清理自己新增的断点，保留用户已有断点。
- 本项目使用 Redis 和 MongoDB，不默认套用 JDBC/SQL 工具。若任务确实涉及其他数据库，先检查实际连接配置和目标环境。
- 数据写入、清理或不可逆操作前，明确目标和授权范围；不确定环境或影响时先确认。集成测试的清库条件严格遵循开发指南，不因库名符合规则就假定数据可以丢弃。

## Git、终端与工具配置

- Git 状态、差异、日志和提交优先使用原生 `git`；一般构建和脚本使用当前会话的终端工具。只有依赖 IDE 运行配置时才使用 IDEA 终端能力。
- 当前开发环境为 Windows；PowerShell 和 Git Bash 的路径及参数引用方式不同，按实际 shell 编写命令，不根据历史会话的系统标识作判断。
- IDEA MCP 不同接口的参数命名可能不同，调用前检查当前工具声明；参数报错时按声明或错误提示修正，不照搬其他客户端的调用字符串。
- Codex 和 Claude Code 的 MCP、权限、技能及本机配置分别配置。共享文档约定工作方式，不会自动安装工具或授予权限。
- 不将本机凭据、工具会话记录或临时配置加入版本库。需要共享的操作结论写入项目文档。
